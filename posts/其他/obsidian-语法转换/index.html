本站的写作链路是 Obsidian 写作 → Hugo 构建 → GitHub Pages 部署（整体方案见 博客构建方案）。问题在于：Obsidian 有一批自己的专有语法，Hugo 的 Goldmark 并不认识。要让笔记原样发布成博客，就得在两个层面做兼容——构建期转换和渲染期兼容。

两层机制 #

Obsidian 的语法分两类，处理方式完全不同：

语法是否标准 Markdown处理层处理者
![[图片]] 嵌入✗ Obsidian 专有构建期文本替换scripts/sync.sh
[[双链]] / [[页面|别名]]✗ Obsidian 专有构建期文本替换scripts/sync.sh
> [!note] Callout✗ Obsidian/GitHub 扩展渲染期Hugo Goldmark + 主题钩子
- [ ] 任务列表✓ GFM 标准渲染期Goldmark 默认
==高亮== / ~~删除线~~~ 扩展渲染期Goldmark extras 扩展

核心分工：能靠 Goldmark 或其扩展直接解析的，交给渲染期，稳妥可靠；Goldmark 完全不认的 Obsidian 专有链接/图片语法，才在 Hugo 跑之前用脚本做文本替换。

构建期：sync.sh 转换 #

![[]] 和 [[]] 不是标准 Markdown，Hugo 直接当纯文本输出。构建脚本 scripts/sync.sh 在 Hugo 运行前把它们改写成标准语法。它做四件事：

1. 归集图片附件 #

Obsidian 的图片散落在各分类目录的 attachments/ 下。脚本递归找出所有 attachments/ 目录，把里面的图片统一拷贝到 static/images/，这样 Hugo 就能以 /images/xxx.png 访问。

2. 转换图片嵌入 #

![[attachments/示意图.png]]   →   ![示意图.png](/images/示意图.png)

只保留文件名（丢掉 attachments/ 前缀），文件名里的空格编码成 %20。

3. 转换双链（关键） #

双链最麻烦的是：Obsidian 里 [[博客构建方案]] 只写文件名，但 Hugo 的真实 URL 带着分类子目录 /posts/其他/博客构建方案/。脚本先扫描整个 content/posts/，建一张 文件名 → 真实 URL 的索引：

博客构建方案  →  /posts/其他/博客构建方案/

再按索引替换，两种写法都支持：

[[博客构建方案]]           →   [博客构建方案](/posts/其他/博客构建方案/)
[[博客构建方案|搭建教程]]   →   [搭建教程](/posts/其他/博客构建方案/)

找不到对应文章时回退到 /posts/<文件名>/。这就是本文开头那个链接的由来——正文里写的其实是 [[博客构建方案]]，构建时被替换成了真实链接。

4. 补全 front matter #

对缺少 front matter 的文件，用文件名当标题、文件修改时间当日期，自动补一段默认头部，避免 Hugo 构建报错。

一个关键细节：跳过代码块 #

转换用的正则会优先匹配围栏代码块（fenced code）和行内代码（inline code），命中就原样保留、不做替换。所以把双链写在代码块里当示例，不会被误替换——本文前面那几处代码块中的 [[双链]]，发布后依然是字面量。

破坏性提醒

sync.sh 是就地修改源文件的。本地 make serve 会跑它，调试完用 make clean（内部 git checkout content/posts/）还原。生产环境由 GitHub Actions 在构建前自动跑，不影响仓库里的源文件。

渲染期：主题与 Goldmark 兼容 #

另一批语法不需要文本替换，靠 Hugo 的 Markdown 引擎和主题就能正确渲染。

Callout 标注块 #

Hugo 0.132+ 内置解析 GitHub/Obsidian 的警告语法，在 blockquote 渲染钩子里暴露 .AlertType、.AlertTitle。主题的 _markup/render-blockquote.html 命中后按类型渲染成带图标、带配色的卡片：

> [!note] 自定义标题
> 正文内容。

> [!warning]
> 不写标题时自动用类型名。

支持 note / tip / warning / danger / question / quote 等类型，各有配色和图标。好处是不用脆弱的正则去解析 Markdown，正确性由 Goldmark 保证。

任务列表 #

GFM 标准语法，Goldmark 默认开启，生成 <input type=checkbox>，主题只负责美化（已完成项加删除线）：

- [ ] 待办
- [x] 已完成

高亮与删除线 #

==高亮== 需要在 hugo.toml 里打开 Goldmark 的 extras 扩展：

[markup.goldmark.extensions.extras.mark]
enable = true      # ==高亮== → <mark>
[markup.goldmark.extensions.extras.delete]
enable = true      # ~~删除线~~ → <del>

再配合 unsafe = true 允许正文里的原始 HTML（Obsidian 笔记常夹带 HTML 片段），这批行内语法就都能正常渲染了。

为什么这样分层 #

一句话总结取舍：能交给解析器的绝不用正则。

  • Callout、任务列表、高亮这些有成熟的 Goldmark 支持，放渲染期，语法边界由解析器兜底，遇到嵌套、转义都不出错；
  • ![[]]、[[]] 是 Obsidian 独有、Goldmark 无从下手的，才在构建期做文本替换——而且替换正则也特意先吃掉代码块，避免误伤示例。

这样写笔记时完全用 Obsidian 的习惯，发布出来就是干净的标准 HTML，两边都不用迁就。

源码 #

#!/bin/bash
# sync.sh - 将 Obsidian 笔记转换为 Hugo 兼容格式
# 用法: ./scripts/sync.sh [content_root]
#
# 处理内容:
# 1. 递归收集所有 attachments/ 目录下的图片到 static/images/
# 2. 转换 ![[图片]] 为标准 Markdown 图片语法
# 3. 转换 [[双链]] 为 Hugo 实际路径（按目录索引解析）
# 4. 为缺少 front matter 的文件添加默认头部

set -euo pipefail

# 默认内容根目录（包含 posts/ 等子目录）
CONTENT_ROOT="${1:-content/posts}"
PROJECT_ROOT="$(cd "$(dirname "$0")"/.. && pwd)"
STATIC_IMAGES_DIR="${PROJECT_ROOT}/static/images"
LINK_INDEX_FILE=""

# 颜色输出
RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
NC='\033[0m'

log_info() { echo -e "${GREEN}[INFO]${NC} $1"; }
log_warn() { echo -e "${YELLOW}[WARN]${NC} $1"; }
log_error() { echo -e "${RED}[ERROR]${NC} $1"; }

cleanup() {
    [ -n "$LINK_INDEX_FILE" ] && [ -f "$LINK_INDEX_FILE" ] && rm -f "$LINK_INDEX_FILE"
}
trap cleanup EXIT

# 递归拷贝所有 attachments/ 目录下的图片到 static/images/
# Obsidian 的图片可能分散在 content/posts/<分类>/attachments/ 下，需全部归集
copy_attachments() {
    mkdir -p "$STATIC_IMAGES_DIR"
    local count=0
    while IFS= read -r -d '' attach_dir; do
        # 拷贝该 attachments 目录下的所有文件（不递归子目录，Obsidian 默认是平铺）
        find "$attach_dir" -maxdepth 1 -type f -print0 | while IFS= read -r -d '' f; do
            cp "$f" "$STATIC_IMAGES_DIR/"
        done
        count=$((count + 1))
    done < <(find "$CONTENT_ROOT" -type d -name "attachments" -print0)
    log_info "已归集 ${count} 个 attachments 目录的图片到 static/images/"
}

# 构建文章索引：basename(无扩展名) → Hugo URL 路径
# 例: content/posts/其他/博客构建方案.md → 博客构建方案 → /posts/其他/博客构建方案/
build_link_index() {
    LINK_INDEX_FILE=$(mktemp)
    # 取 CONTENT_ROOT 相对项目根的位置作为 URL 前缀（content/posts → /posts）
    local url_root_prefix
    url_root_prefix=$(echo "$CONTENT_ROOT" | sed 's|^content||; s|/*$||')

    while IFS= read -r -d '' file; do
        local fname rel url_path
        fname=$(basename "$file" .md)
        # 跳过 _index.md（分类聚合页，不是文章）
        [ "$fname" = "_index" ] && continue

        # 相对 CONTENT_ROOT 的目录部分
        rel="${file#$CONTENT_ROOT/}"
        rel=$(dirname "$rel")
        if [ "$rel" = "." ]; then
            url_path="${url_root_prefix}/${fname}/"
        else
            url_path="${url_root_prefix}/${rel}/${fname}/"
        fi

        # 写入索引: basename<TAB>url_path
        printf '%s\t%s\n' "$fname" "$url_path" >> "$LINK_INDEX_FILE"
    done < <(find "$CONTENT_ROOT" -name "*.md" -type f -print0)

    log_info "已构建 $(wc -l < "$LINK_INDEX_FILE" | tr -d ' ') 条文章索引"
}

# 检查文件是否有 front matter
has_front_matter() {
    head -1 "$1" | grep -q "^---$"
}

# 为文件添加默认 front matter
add_front_matter() {
    local file="$1"
    local filename title date
    filename=$(basename "$file" .md)
    title=$(echo "$filename" | sed 's/-/ /g')
    date=$(date -r "$file" "+%Y-%m-%dT%H:%M:%S+08:00" 2>/dev/null || date "+%Y-%m-%dT%H:%M:%S+08:00")

    local temp_file
    temp_file=$(mktemp)
    cat > "$temp_file" << EOF
---
title: "${title}"
date: ${date}
draft: false
publish: true
tags: []
categories: []
---

EOF
    cat "$file" >> "$temp_file"
    mv "$temp_file" "$file"
    log_info "添加 front matter: $file"
}

# 转换 Obsidian 语法：图片 + 双链
# 跳过代码块（``` ```）和内联代码（` `）中的内容
# 图片: ![[path/name.png]] → ![name.png](/images/name.png)（空格 %20，只保留 basename）
# 双链: [[page|alias]]     → [alias](URL)
#       [[page]]           → [page](URL)
# URL 来自 LINK_INDEX_FILE；找不到时回退到 /posts/<basename>/
convert_obsidian_syntax() {
    local file="$1"

    grep -qE '!\[\[|\[\[' "$file" || return 0

    LINK_INDEX="$LINK_INDEX_FILE" perl -i -0777 -pe '
        BEGIN {
            our %INDEX;
            my $idx = $ENV{LINK_INDEX};
            if ($idx && open(my $fh, "<", $idx)) {
                local $/ = "\n";  # -0777 把 $/ 设为 undef（slurp 模式），需在此显式按行读
                while (my $line = <$fh>) {
                    chomp $line;
                    my ($name, $url) = split /\t/, $line, 2;
                    $INDEX{$name} = $url if defined $url;
                }
                close $fh;
            }
        }
        sub resolve_link {
            my ($path) = @_;
            $path =~ s|.*/||;        # 取 basename
            $path =~ s/\.md$//;      # 去 .md 后缀
            return $INDEX{$path} // "/posts/$path/";
        }
        s{
            (```.*?```)              # $1: fenced code
            |(`[^`]+`)               # $2: inline code
            |(!\[\[([^\]]+)\]\])     # $3: image, $4: filename
            |(\[\[([^\]|]+)\|([^\]]+)\]\])  # $5: alias link, $6: target, $7: text
            |(\[\[([^\]]+)\]\])      # $8: plain link, $9: target
        }{
            if (defined $1) { $1 }
            elsif (defined $2) { $2 }
            elsif (defined $3) {
                my $f = $4;
                $f =~ s|.*/||;
                my $alt = $f;
                $f =~ s/ /%20/g;
                "![$alt](/images/$f)"
            }
            elsif (defined $5) {
                my $url = resolve_link($6);
                "[$7]($url)"
            }
            elsif (defined $8) {
                my $name = $9; $name =~ s|.*/||; $name =~ s/\.md$//;
                my $url = resolve_link($9);
                "[$name]($url)"
            }
            else { $& }
        }gsex;
    ' "$file"

    log_info "转换 Obsidian 语法: $file"
}

main() {
    log_info "开始同步: ${CONTENT_ROOT}"

    if [ ! -d "$CONTENT_ROOT" ]; then
        log_error "内容目录不存在: $CONTENT_ROOT"
        exit 1
    fi

    # 1. 归集图片
    copy_attachments

    # 2. 建文章索引
    build_link_index

    # 3. 处理每个 markdown 文件
    while IFS= read -r -d '' file; do
        log_info "处理文件: $file"
        if ! has_front_matter "$file"; then
            add_front_matter "$file"
        fi
        convert_obsidian_syntax "$file"
    done < <(find "$CONTENT_ROOT" -name "*.md" -type f -print0)

    log_info "同步完成"
}

main "$@"
