本站用的主题 snowfalling 是从零手写的，没有基于 PaperMod、Ananke 之类的现成主题改。这篇文章记录它的设计取舍、怎么用，以及内部是怎么组织的。

为什么自己写主题 #

现成主题上手快，但有两个长期痛点：一是想改点样式往往要跟主题作者的抽象层斗争，二是主题更新和自己的定制经常冲突。既然是个人博客，功能面并不大，索性自己写一套，换来的是每一行 CSS/JS 都能看懂、都能改。

定下四条设计原则：

  1. 完全自包含：不依赖 Bootstrap、jQuery 或任何 Hugo Module，所有样式、脚本、图标都内置在主题目录，只用 Hugo Extended 自带的 SCSS 编译与 js.Build。克隆仓库不需要 --recurse-submodules。
  2. CSS 变量驱动主题：明暗两套配色用 CSS 自定义属性表达，切换只需翻转 <html data-theme>，不用重新编译或加载第二份 CSS。
  3. 渐进增强：核心内容（文章、导航）纯 HTML/CSS 就能用，JS 只负责主题切换、移动端菜单、搜索这些增强能力。
  4. 原生优先：交互全部原生 JS，图标是内联 SVG，避免图标字体和运行时依赖。

特性一览 #

  • 明暗双主题：跟随系统偏好自动切换，也可手动切换并记忆（localStorage），首屏无闪烁
  • Obsidian 语法兼容：Callout 标注块（> [!note] 等）、任务列表、==高亮==、~~删除线~~
  • 纯前端搜索：基于 index.json 索引，支持标题/正文/标签匹配，快捷键 / 或 Ctrl/Cmd+K
  • 文章目录（TOC）：自动生成，锚点定位
  • 代码高亮：Chroma 类名渲染，明暗模式各自配色
  • 响应式：移动端折叠菜单

怎么用 #

启用主题 #

主题放在 themes/snowfalling/，在站点配置里启用：

# config/_default/hugo.toml
theme = "snowfalling"

必要的 Hugo 配置 #

主题依赖几项 Hugo 配置才能完整工作（本仓库已配好）：

# 搜索索引：首页额外输出 JSON
[outputs]
home = ["HTML", "RSS", "JSON"]

# 分类法
[taxonomies]
tag = "tags"
category = "categories"

# Markdown：Obsidian 语法支持
[markup]
[markup.goldmark.renderer]
unsafe = true                      # 允许正文 HTML
[markup.goldmark.extensions.extras.mark]
enable = true                      # ==高亮==
[markup.goldmark.extensions.extras.delete]
enable = true                      # ~~删除线~~
[markup.highlight]
noClasses = false                  # 代码高亮用 CSS 类，交给主题控制配色

站点参数 #

在 config/_default/params.toml 里配置品牌、SEO、社交链接等：

logo_text = "Ronald's Blog"        # 页头品牌文字
hero_description = "记录学习与思考的个人技术博客"
mainSections = ["posts"]           # 参与列表/归档/搜索的板块
copyright = "© 2026 Ronald's Blog"

[search]
enable = true
placeholder = "搜索文章…"

[[social]]                         # 页脚社交链接
name = "GitHub"
icon = "github"
url = "https://github.com/snowfalling"

菜单在 config/_default/menus.zh.toml 定义，文章的 front matter 规范与其他文章一致（title / date / tags / categories / ShowToc 等）。

换色与换字体 #

不用碰任何组件样式，只改 themes/snowfalling/assets/scss/_variables.scss 里 :root 和 [data-theme="dark"] 下的 CSS 变量：

  • --sf-brand 品牌主色
  • --sf-bg / --sf-surface 背景
  • --sf-text / --sf-heading 文字
  • --sf-container 正文阅读宽度

字体在 head.html 的 Google Fonts 链接和 --sf-font-sans / --sf-font-mono 里调整。

覆盖模板 #

想改某个模板又不想动主题源码，在站点根目录 layouts/ 下建同名文件即可——Hugo 查找顺序是站点优先于主题。

内部架构 #

目录结构 #

themes/snowfalling/
├── archetypes/default.md      # hugo new 文章模板
├── assets/
│   ├── scss/                  # 样式源，编译为单一 CSS
│   │   ├── main.scss          # 入口，@import 各模块
│   │   ├── _variables.scss    # 设计令牌（明暗两套 CSS 变量）
│   │   ├── _base.scss         # reset + 元素基线
│   │   ├── _layout.scss       # 页头/页脚/容器/导航
│   │   ├── _components.scss   # 卡片/标签/分页/TOC/按钮
│   │   ├── _content.scss      # 正文排版
│   │   ├── _code.scss         # 代码块 + Chroma 高亮配色
│   │   ├── _obsidian.scss     # Callout / 任务列表 / 高亮
│   │   ├── _search.scss       # 搜索弹层
│   │   └── _responsive.scss   # 移动端适配
│   └── js/
│       ├── theme-init.js      # 防闪烁主题初始化（head 内联执行）
│       └── main.js            # 主题切换 + 菜单 + 搜索
└── layouts/
    ├── index.html             # 首页
    ├── partials/              # head/header/footer/icons/toc/post-card…
    └── _default/              # baseof/single/list/terms/archives/search/index.json

页面渲染流程 #

所有页面都经过布局骨架 _default/baseof.html：

baseof.html
├── <head> → partials/head.html
│             ├── theme-init.js（内联，CSS 前同步执行 → 定 data-theme）
│             └── scss/main.scss → toCSS →（生产环境 fingerprint）→ <link>
├── partials/header.html      # 吸顶导航 + 搜索/主题/菜单按钮
├── <main> → {{ block "main" }}  # 各页面模板填充
├── partials/footer.html
├── partials/search-modal.html
└── partials/scripts.html     # main.js → js.Build → <script defer>

各页面模板用 {{ define "main" }} 注入主体。模板选择：

内容模板
首页index.html
文章详情_default/single.html
/posts/、/tags/xxx/、/categories/xxx/_default/list.html
/tags/、/categories/ 索引（标签云）_default/terms.html
归档页_default/archives.html
搜索页_default/search.html

明暗切换机制 #

关键在 CSS 变量分层：

:root               { --sf-bg: #fcfdfd; --sf-text: #2b3138; /* 亮色 */ }
[data-theme="dark"] { --sf-bg: #0f1419; --sf-text: #cdd6df; /* 暗色 */ }

组件只引用变量（background: var(--sf-bg)），从不写死颜色。切换流程分三步：

  1. 首屏防闪烁：theme-init.js 在 <head> 内联同步执行，先读 localStorage.sf-theme，没有再读系统 prefers-color-scheme，据此设置 <html data-theme>。因为在 CSS 应用之前执行，暗色用户不会先看到一下亮色。核心就几行：

    var stored = localStorage.getItem("sf-theme");
var prefersDark = window.matchMedia &&
  window.matchMedia("(prefers-color-scheme: dark)").matches;
var theme = stored || (prefersDark ? "dark" : "light");
document.documentElement.setAttribute("data-theme", theme);

  2. 手动切换：main.js 的按钮翻转 data-theme 并写回 localStorage。

  3. CSS 变量随属性变化即时生效，transition 让背景/文字平滑过渡。

样式编译 #

head.html 里用 Hugo Extended 内置的 libsass 编译，无需外部 dart-sass：

{{ $opts := dict "transpiler" "libsass" "outputStyle" (cond hugo.IsProduction "compressed" "expanded") }}
{{ $style := resources.Get "scss/main.scss" | toCSS $opts }}
{{ if hugo.IsProduction }}{{ $style = $style | fingerprint }}{{ end }}

生产环境压缩 + 加指纹（缓存失效）；JS 同理经 js.Build 打包，生产压缩 + 指纹 + SRI。

Obsidian 兼容实现 #

Callout 没有用脆弱的正则去解析 Markdown，而是借 Hugo 0.132+ 内置的 GitHub/Obsidian 警告语法解析：blockquote 渲染钩子里能拿到 .Type == "alert"、.AlertType、.AlertTitle。_markup/render-blockquote.html 命中 alert 就按类型映射图标、渲染成 .callout[data-callout=type] 结构，再由 _obsidian.scss 按属性选择器注入对应主题色。正确性由 Goldmark 保证。

任务列表、==高亮== 则靠 Goldmark 的扩展开关生成标准 HTML，主题只负责美化。而 ![[img]]、[[page]] 这类双链在 Hugo 之前就由构建脚本 scripts/sync.sh 转成了标准 Markdown，主题不介入。

纯前端搜索 #

零依赖、零后端：

  1. 配置让首页额外输出 JSON，由 _default/index.json 渲染，收录 mainSections 文章的标题/链接/标签/正文纯文本，生成 /index.json
  2. search-modal.html 提供搜索弹层结构，data-index 指向这个 JSON
  3. main.js 的 setupSearch()：首次打开时 fetch 索引 → 输入时按标题/正文/标签过滤 → 高亮关键词 → 键盘上下选择、回车跳转
  4. 快捷键 /、Ctrl/Cmd+K 打开，Esc 关闭

权衡：索引大小随文章数线性增长。文章上千篇时应改成分片或引入 FlexSearch，但当前个人博客规模完全够用。

扩展指引 #

需求做法
改配色/字体改 _variables.scss 的 CSS 变量
加图标在 icons.html 增一个分支（内联 SVG）
加 Callout 类型在 render-blockquote.html 图标映射 + _obsidian.scss 配色各加一条
加页面类型在 layouts/_default/ 加模板，或用 layout: front matter 指定
覆盖主题模板站点根 layouts/ 建同名文件
替换搜索引擎改 main.js 的 setupSearch() 与 index.json 索引字段

小结 #

snowfalling 的核心取舍是用自包含换可控性：放弃现成主题的开箱即用，换来每一处样式和交互都能直接改、不跟上游冲突。CSS 变量驱动明暗、Goldmark 钩子做 Obsidian 兼容、静态 JSON 做前端搜索，这三点是它区别于随手改一个现成主题的地方。对个人博客这个体量，这套架构维护成本很低，也足够清爽。
