Hugo 文章目录（TOC）生成机制与踩坑

目录是怎么来的 #

Hugo 的文章目录不是主题手写的，而是 Markdown 渲染器根据正文里的标题（#、##……）自动扫描生成的。在模板里通过页面变量 .TableOfContents 拿到一段现成的 <nav> HTML：

{{ .TableOfContents }}

它输出的结构大致是嵌套的 <ul>/<li>，每个 <li> 对应一个标题、锚点指向标题的自动 id。你能控制的只有「哪些标题进目录」和「怎么渲染这段 HTML」，标题本身的层级关系由正文决定。

三个关键配置项 #

在 hugo.toml 里：

[markup.tableOfContents]
startLevel = 2   # 从哪一级标题开始收录
endLevel = 4     # 收录到哪一级为止
ordered = false  # true 输出有序列表 <ol>，false 输出 <ul>
  • startLevel = 2 意味着 H1（#）不会进目录，从 H2（##）开始收。
  • endLevel = 4 表示比 H4 更深的标题（H5/H6）不进目录。
  • 只有落在 [startLevel, endLevel] 区间内的标题才会出现在目录里。

主题侧的渲染逻辑 #

拿到 .TableOfContents 之后，是否显示、怎么显示由主题的 partial 决定。本站主题 layouts/partials/toc.html：

{{ if and (default true .Params.ShowToc) (gt (len .TableOfContents) 100) }}
<nav class="toc" {{ if .Params.TocOpen }}open{{ end }}>
  <div class="toc__title">
    {{ partial "icons.html" "list" }}
    <span>目录</span>
  </div>
  {{ .TableOfContents }}
</nav>
{{ end }}

两个判断条件：

  • default true .Params.ShowToc：文章 front matter 里 ShowToc: false 才会关闭目录，默认开启。
  • gt (len .TableOfContents) 100：目录 HTML 长度大于 100 字符才渲染——用来过滤掉「只有一两个标题、几乎没内容」的空目录。

front matter 里的相关字段：

ShowToc: true    # 是否显示目录
TocOpen: true    # 目录默认展开还是折叠

踩坑复盘：目录残缺、层级错乱 #

某篇文章的正文标题是这样写的：

# PECS
## 为什么需要它？
# 示例
## 便于理解

期望目录里有四条、两级嵌套，结果生成出来只剩两条、还是断裂的：

· 为什么需要它？
· 便于理解

两个真正的章节标题 PECS、示例 完全消失，剩下的两个子标题被拆进了两个互不相连的列表，层级是断的。

原因 #

配置里 startLevel = 2，也就是 H1 一律不进目录。而这篇文章误把 #（H1）当成了正文分节标题：

  1. 两个 # 章节标题 PECS、示例 因低于 startLevel 被整个丢弃；
  2. 只剩两个 ## 子标题，但它们的父级 H1 没了，Hugo 只能把每个 H2 各自塞进一个独立 <ul>，于是目录变得扁平、断裂、还缺章节名。

本质 #

博客文章的主标题来自 front matter 的 title:，页面里已经渲染成大标题。正文里不应再用 #（H1），H1 是留给页面标题的，正文章节应从 ##（H2）起。

修复就是把正文所有标题整体降一级，保持相对层级：

## PECS
### 为什么需要它？
## 示例
### 便于理解

改完后 PECS、示例 作为 H2 成为目录顶层，为什么需要它？、便于理解 作为 H3 正确缩进在各自章节下。

写作规范小结 #

  • 正文标题从 ##（H2）开始，不要用 #（H1）——H1 是页面标题。
  • 标题层级要连续，不要从 ## 直接跳到 ####，否则目录缩进会错乱。
  • 目录只收 H2~H4（由 startLevel/endLevel 决定），更深的标题不会出现在目录里，别指望用 H5/H6 组织大纲。
  • 不想要目录的文章，在 front matter 里加 ShowToc: false。
