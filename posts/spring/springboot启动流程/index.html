springboot启动流程

Spring Boot 的启动看似只有一行 SpringApplication.run(App.class, args)，但背后是一套完整的初始化编排。本文按时间顺序拆解整个流程，并标出关键节点。

一、入口：main 方法与 run 调用 #

@SpringBootApplication
public class MyApp {
    public static void main(String[] args) {
        SpringApplication.run(MyApp.class, args);
    }
}

@SpringBootApplication 是一个组合注解，包含三个核心注解：@SpringBootConfiguration（标记这是配置类）、@ComponentScan（开启组件扫描，默认扫描当前类所在包及子包）、以及最关键的 @EnableAutoConfiguration（开启自动装配）。

SpringApplication.run() 实际分两步：先 new SpringApplication() 构造实例，再调用实例的 run(args) 方法。

二、SpringApplication 实例的构造阶段 #

构造函数里主要做了几件准备工作。

推断应用类型。 Spring Boot 会检查 classpath 上有哪些类存在。如果有 DispatcherServlet 相关的 Servlet 类，就判定为 SERVLET 类型（传统 Web）；如果是 WebFlux 的响应式类，则是 REACTIVE；两者都没有则是 NONE。这个判断决定了后面创建哪种 ApplicationContext。

static WebApplicationType deduceFromClasspath() {
    if (isPresent("...DispatcherHandler") && !isPresent("...DispatcherServlet"))
        return WebApplicationType.REACTIVE;    // WebFlux
    for (String c : SERVLET_INDICATOR_CLASSES)
        if (!isPresent(c)) return WebApplicationType.NONE;
    return WebApplicationType.SERVLET;         // 传统 Web MVC
}

加载扩展点。 ApplicationContextInitializer 和 ApplicationListener 都是通过 spring.factories 机制（META-INF/spring.factories 文件）从各个 jar 里读取出来的，用 SpringFactoriesLoader 加载。

推断主启动类，即包含 main 方法的那个类，用于后续日志展示等。

三、run 方法的核心执行流程 #

这是启动的主干：

public ConfigurableApplicationContext run(String... args) {
    StopWatch stopWatch = new StopWatch();
    stopWatch.start();                                   // ① 启动计时
    ConfigurableApplicationContext context = null;
    SpringApplicationRunListeners listeners = getRunListeners(args);
    listeners.starting(...);                             // ② 发布 starting 事件
    ApplicationArguments arguments = new DefaultApplicationArguments(args);
    ConfigurableEnvironment env = prepareEnvironment(listeners, arguments); // ③ 环境准备
    printBanner(env);                                    // ④ Banner
    context = createApplicationContext();                // ⑤ 创建容器
    prepareContext(context, env, listeners, arguments);  // ⑥ 准备容器
    refreshContext(context);                             // ⑦ 刷新容器(核心)
    afterRefresh(context, arguments);
    stopWatch.stop();
    listeners.started(context);
    callRunners(context, arguments);                     // ⑧ 调用 Runners
    listeners.running(context);                          // ReadyEvent
    return context;
}

关键节点说明：

① 启动计时。 记录启动耗时，最终日志里的 “Started App in X seconds” 就来自这里。

② 创建并启动 RunListeners。 主要是 EventPublishingRunListener，负责在启动各阶段发布事件（如 ApplicationStartingEvent），实现启动过程的可观测和可扩展。

③ 准备 Environment（关键节点）。 创建 ConfigurableEnvironment，把命令行参数、系统属性、系统环境变量、以及 application.yml/properties 等配置源加载进来。这里会发布 ApplicationEnvironmentPreparedEvent，ConfigDataEnvironmentPostProcessor 就是在这个阶段解析配置文件的。Profile（如 dev/prod）也在此确定。

④ 打印 Banner。 就是控制台那个 Spring 的字符画，可自定义。

⑤ 创建 ApplicationContext（关键节点）。 根据前面推断的应用类型创建对应容器。Servlet Web 应用创建的是 AnnotationConfigServletWebServerApplicationContext，这个容器类型是内嵌 Web 服务器能力的关键。

⑥ prepareContext。 把 Environment 设置进容器，执行前面加载的 ApplicationContextInitializer，并把主配置类注册为 Bean 定义（作为 Bean 定义的起点）。发布 ApplicationPreparedEvent。

⑦ refreshContext（核心）。 调用 Spring 的 AbstractApplicationContext.refresh()，这是 Spring IoC 容器的标准生命周期，也是最重要的节点，详见下一节。

⑧ afterRefresh 与 Runners。 刷新完成后，调用所有 ApplicationRunner 和 CommandLineRunner，这是留给开发者在启动完成后执行自定义逻辑的钩子。发布 ApplicationStartedEvent 和 ApplicationReadyEvent。

四、refresh() 内部：IoC 容器的生命周期 #

refresh() 方法内部按固定顺序执行一系列步骤：

public void refresh() {
    prepareRefresh();
    ConfigurableListableBeanFactory bf = obtainFreshBeanFactory();
    prepareBeanFactory(bf);
    invokeBeanFactoryPostProcessors(bf);   // ★ 解析配置/自动装配/组件扫描
    registerBeanPostProcessors(bf);
    finishBeanFactoryInitialization(bf);   // ★ 实例化所有非懒加载单例 Bean
    onRefresh();                           // ★ Web 应用启动内嵌 Tomcat
    finishRefresh();                       // 发布 ContextRefreshedEvent
}

prepareBeanFactory 准备 BeanFactory，设置类加载器、注册内置 Bean 等。

invokeBeanFactoryPostProcessors 执行 BeanFactoryPostProcessor。自动装配的核心就发生在这里：ConfigurationClassPostProcessor 会解析配置类，处理 @ComponentScan 扫描组件，并处理 @EnableAutoConfiguration。自动装配通过 AutoConfigurationImportSelector 读取所有 jar 中 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports（旧版本是 spring.factories）里列出的自动配置类，再结合 @Conditional 系列条件注解（如 @ConditionalOnClass、@ConditionalOnMissingBean）决定哪些配置生效。这就是"约定优于配置"的实现机制。

@Configuration
@ConditionalOnClass({ Servlet.class, DispatcherServlet.class })
@ConditionalOnMissingBean(WebMvcConfigurationSupport.class)
public class WebMvcAutoConfiguration { ... }

registerBeanPostProcessors 注册 BeanPostProcessor，为后续 AOP、依赖注入等做准备。

finishBeanFactoryInitialization 实例化所有非懒加载的单例 Bean，完成依赖注入、属性填充、初始化回调（@PostConstruct、InitializingBean、AOP 代理生成等）。绝大多数业务 Bean 都在这一步被创建好。

onRefresh（关键 Web 节点）在 Web 应用中会创建并启动内嵌 Web 服务器。ServletWebServerApplicationContext 重写了 onRefresh，通过 ServletWebServerFactory（默认 TomcatServletWebServerFactory）创建 Tomcat 实例并启动，绑定端口开始监听。DispatcherServlet 也在此过程中注册进 Servlet 容器。这就是为什么 Spring Boot 不需要外部部署 war 包。

@Override
protected void onRefresh() {
    super.onRefresh();
    createWebServer();          // 创建并启动内嵌服务器
}

private void createWebServer() {
    ServletWebServerFactory factory = getWebServerFactory(); // 默认 Tomcat
    this.webServer = factory.getWebServer(getSelfInitializer());
    // getWebServer() 内部 new Tomcat()、绑定端口、注册 DispatcherServlet
}

finishRefresh 发布 ContextRefreshedEvent，完成收尾。

五、启动完成 #

服务器已监听端口，容器就绪，ApplicationReadyEvent 发布，应用正式对外提供服务。控制台打印类似 Tomcat started on port(s): 8080 和 Started MyApp in 3.2 seconds。

关键节点小结 #

如果只记几个最重要的转折点：应用类型推断（决定 Web 还是非 Web）、Environment 准备（加载配置文件）、容器创建（选择内嵌 Web 容器类型）、invokeBeanFactoryPostProcessors（自动装配发生地）、finishBeanFactoryInitialization（Bean 批量实例化）、onRefresh（内嵌 Tomcat 启动）、以及最后的 Runners 和 ReadyEvent。

其中，自动装配（@EnableAutoConfiguration + 条件注解）和内嵌服务器启动（onRefresh 中创建 Tomcat）是 Spring Boot 区别于传统 Spring 的两个最核心特性。
