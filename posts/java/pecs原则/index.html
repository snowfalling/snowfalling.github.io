PECS原则

PECS 是 Java 泛型中的一个实用准则，全称是 Producer Extends, Consumer Super，由 Joshua Bloch 在《Effective Java》中提出。核心思想是：如果一个参数化类型是数据的生产者（你从中读取），用 ? extends T；如果是数据的消费者（你往里写入），用 ? super T。

为什么需要它？ #

Java 的泛型是不变的（invariant）：List<Dog> 不是 List<Animal> 的子类型，即使 Dog extends Animal。通配符是打破这个限制的方式，而 PECS 告诉你该选哪种通配符。

Producer Extends（读取用 extends）

当你只需要从集合中取出元素时：

public double sum(List<? extends Number> list) {
    double s = 0;
    for (Number n : list) s += n.doubleValue(); // 读取，OK
    // list.add(1);  // 编译错误！不能写入
    return s;
}

这样 List<Integer>、List<Double> 都能传进来。编译器知道取出的一定是 Number 的子类，所以读取安全；但不知道具体是哪个子类，所以禁止写入。

Consumer Super（写入用 super）

当你只需要往集合中放入元素时：

public void fill(List<? super Integer> list) {
    list.add(1);    // 写入，OK
    list.add(2);
    // Integer x = list.get(0);  // 编译错误！取出只能当 Object
}

List<Integer>、List<Number>、List<Object> 都能传进来。编译器知道容器至少能装 Integer，所以写入安全；但取出时只能保证是 Object。

一个典型例子：Collections.copy

public static <T> void copy(List<? super T> dest, List<? extends T> src) {
    for (int i = 0; i < src.size(); i++)
        dest.set(i, src.get(i));  // 从 src 读，往 dest 写
}

src 是生产者（读） → extends，dest 是消费者（写） → super。

简单记法： 往外拿东西的用 extends，往里塞东西的用 super，又拿又塞就用精确类型 T，不用通配符。

示例 #

  
import java.util.ArrayList;  
import java.util.Arrays;  
import java.util.Collections;  
import java.util.List;  
  
/**  
 * PECS 原则演示：Producer Extends, Consumer Super * * 场景：一个电商系统要把「某个品类的商品」汇总进「总商品清单」里。 *  - src（源清单）：我们只从里面【读取】商品 —— 它是生产者(Producer) -> ? extends T *  - dest（目标清单）：我们把商品【写入】它     —— 它是消费者(Consumer) -> ? super T * * 对应 JDK 签名： *   public static <T> void copy(List<? super T> dest, List<? extends T> src)  
 */public class PecsDemo {  
  
  // 简单的商品类型层次  
  static class Product {  
    final String name;  
    Product(String name) { this.name = name; }  
    @Override public String toString() { return getClass().getSimpleName() + "(" + name + ")"; }  
  }  
  static class Book extends Product {  
    Book(String name) { super(name); }  
  }  
  
  static class Pen extends Product {  
    Pen(String name) { super(name); }  
  }  
  
  
  public static void main(String[] args) {  
  
    // ---------- 生产者(Producer)：只被读取 ----------  
    // 一批具体的 Book，作为数据来源    List<Book> books = Arrays.asList(new Book("Effective Java"), new Book("Clean Code"));  
  
    // ---------- 消费者(Consumer)：只被写入 ----------  
    // 总清单声明为 Product，目标容器必须“至少能装下 Book”    // 注意：Collections.copy 要求 dest 已有足够容量（size 要 >= src.size）    List<Product> catalog = new ArrayList<>(  
        Arrays.asList(new Product("占位1"), new Product("占位2")));  
  
    // 关键调用：dest 是 List<Product>(即 ? super Book)，src 是 List<Book>(即 ? extends Book)  
    // T 被推断为 Book    Collections.copy(catalog, books);  
  
    System.out.println("拷贝后的总清单：" + catalog);  
    // 输出：拷贝后的总清单：[Book(Effective Java), Book(Clean Code)]  
  
    // ================= 为什么 PECS 是必需的？=================  
    // 1) 生产者用 super 会怎样？—— 读出来的类型退化成 Object，用起来很别扭    //    List<? extends Product> 才能保证：从中读出的每个元素都“至少是”一个 Product    List<? extends Product> producer = books;  
    Product p = producer.get(0);   // ✅ 读：编译器确定 get 出来的是 Product  
    // producer.add(new Book("x"));  // ❌ 写：编译不通过（不知道确切类型，禁止写入）    System.out.println("从 producer 只读：" + p);  
  
    // 2) 消费者用 extends 会怎样？—— 无法安全写入  
    //    List<? super Book> 才能保证：任何 Book 都能安全放进去    List<? super Product> consumer = catalog;  
    consumer.add(new Pen("Refactoring")); // ✅ 写：Book 一定符合 “? super Book”  
    // Book b = consumer.get(0);            // ❌ 读：读出来只能当作 Object    Object o = consumer.get(2);  
    System.out.println("往 consumer 写入后：" + catalog + "，读出的只能当 Object：" + o);  
  }  
}

总结 #

理解 PECS 的关键就三句话，对照这个场景记：

Producer Extends —— src 是数据来源，我们只从它「往外读」。用 List<? extends T> 能保证读出来的每个元素「至少是一个 T」，所以 producer.get(0) 安全；但编译器不知道它确切的子类型，禁止 add，防止你把一个 Book 塞进实际是 List<某种其他Product> 的容器里。

Consumer Super —— dest 是接收方，我们只「往里写」。用 List<? super T> 能保证任何 T（这里是 Book）都能安全放进去，因为容器声明的元素类型是 Book 的某个父类；代价是读出来只能当 Object。

为什么 Collections.copy 要同时用两者：它做的事就是「从 src 读、往 dest 写」，读的一方当生产者(extends)、写的一方当消费者(super)，这样 List<Book> 能拷进 List<Product>,灵活性最大化又不破坏类型安全。

Note

一个易踩的坑：Collections.copy 要求 dest 的 size 已经 ≥ src.size（它是覆盖已有位置，不是追加），所以示例里先用占位元素把 catalog 撑到足够大。如果传空 list 会抛 IndexOutOfBoundsException。
